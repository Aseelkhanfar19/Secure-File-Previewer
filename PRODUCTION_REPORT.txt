 EXECUTIVE SUMMARY
----------------------------------------------------------------
Firebase has been completely removed. All user-uploaded files
(photos, PDFs, any binary the user picks) are now stored in
Supabase Storage in a private bucket, while only a small mapping
row (code -> object path) lives in the Postgres table.

The result is a clean, scalable, RLS-protected backend that:
  * Does not bloat the database with Base64 blobs.
  * Streams binaries through Supabase Storage.
  * Uses only the publishable (anon) API key on the client.
  * Enforces every access path through Row Level Security.

      |  Send                                         |  public.shared_links
      v                                               |    code (PK), file_path,
  SendActivity                                        |    file_name, created_at
      |   1. pick file (any MIME)                    |    RLS: anon -> INSERT/SELECT/DELETE
      |   2. POST bytes to Storage                   |
      |        /storage/v1/object/shared-files/      |  Storage
      |        <uuid>/<filename>                     |  bucket 'shared-files' (private)
      |   3. POST row to PostgREST                   |    RLS: anon -> INSERT/SELECT/DELETE
      |        /rest/v1/shared_links                 |    inside this bucket only
      |   4. show 4-digit code to user               |
      v                                              ^
  SupabaseClient (OkHttp)  --------------------------+
       insertSharedLink / fetchSharedLink
       uploadObject  / downloadObject / deleteObject

 3. DATA MODEL (PRODUCTION)
----------------------------------------------------------------

  Postgres -- public.shared_links
  ------------------------------------------------------------
   code          integer        PRIMARY KEY     (1000..9999)
   file_path     text  NOT NULL                 e.g. "df5fe375-.../report.pdf"
   file_name     text                           e.g. "report.pdf"
   created_at    timestamptz   default now()

  Storage -- bucket "shared-files" (private)
  ------------------------------------------------------------
   object key   = "{uuid}/{filename}"
   stored as    = raw bytes with proper Content-Type

  RLS policies
  ------------------------------------------------------------
   public.shared_links              anon -> INSERT / SELECT / DELETE
   storage.objects (this bucket)    anon -> INSERT / SELECT / DELETE
