 7. Security notes
----------------------------------------------------------------
- The publishable (anon) key is intentionally embedded in BuildConfig. This
  matches Supabase's own guidance: anon keys are safe in client apps as long
  as Row Level Security is enabled. supabase_schema.sql enables RLS.
- The legacy JWT secret and the secret API key (sb_secret_*) must NOT be
  shipped in the Android APK. They are only used server-side. The code in
  this commit does NOT reference either of them.
- After verifying everything works, you should:
    * rotate the legacy JWT secret (only if you used it elsewhere)
    * leave RLS enabled
    * tighten policies later if you want stricter access (for example,
      restrict DELETE to "after 24h" or remove DELETE entirely).
